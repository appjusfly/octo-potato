# Generate INTEGRATION.md

Use this skill to generate the customer-facing integration document. This file tells the customer exactly what their backend needs to implement to work with the HubSpot app.

## When to Use

- App design is complete (objects, webhooks, scopes defined)
- Before or after first upload
- When updating existing INTEGRATION.md after schema changes

## Step 1: Read Current Project State

Gather all information from the project files:

1. `src/app/app-hsmeta.json` — app name, OAuth scopes, redirect URLs
2. `src/app/app-objects/*.json` — all app object schemas
3. `src/app/app-objects/app-object-associations/*.json` — all associations
4. `src/app/webhooks/webhooks-hsmeta.json` — webhook config (if exists)

Create or overwrite `INTEGRATION.md` at the project root with the following sections:

### Authorization URL

### Token Exchange
When HubSpot redirects to your callback with `?code={auth_code}`:

\`\`\`javascript
const response = await fetch('https://api.hubspot.com/oauth/2026-03/token', {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body: new URLSearchParams({
    grant_type: 'authorization_code',
    code: authCode,
    redirect_uri: process.env.HUBSPOT_REDIRECT_URI,
    client_id: process.env.HUBSPOT_CLIENT_ID,
    client_secret: process.env.HUBSPOT_CLIENT_SECRET,
  }),
});

const { access_token, refresh_token, expires_in, hub_id } = await response.json();
// Store tokens keyed by hub_id
\`\`\`

**Important:** All credentials must be sent in the request body, never as URL query parameters.

### Token Refresh
Access tokens expire in **30 minutes** (1800 seconds). Refresh before expiry:

\`\`\`javascript
const response = await fetch('https://api.hubspot.com/oauth/2026-03/token', {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body: new URLSearchParams({
    grant_type: 'refresh_token',
    refresh_token: storedRefreshToken,
    client_id: process.env.HUBSPOT_CLIENT_ID,
    client_secret: process.env.HUBSPOT_CLIENT_SECRET,
  }),
});
\`\`\`

### Token Storage
- Key tokens by `hub_id` (from token response) — one token pair per customer portal
- Store `access_token`, `refresh_token`, and `expires_at` (current time + `expires_in`)
- Refresh tokens never expire unless the app is uninstalled or the token is revoked
- Use a secrets manager or encrypted storage — never store tokens in plain text

## 2. Webhook Receiver Contract

### Endpoint
`POST <targetUrl from webhooks-hsmeta.json>` (HTTPS required)

### Signature Verification (REQUIRED)
Verify every incoming request using `X-HubSpot-Signature-v3` and `X-HubSpot-Request-Timestamp`:

\`\`\`javascript
const crypto = require('crypto');

function verifyWebhookSignature(clientSecret, method, uri, rawBody, timestamp, signature) {
  // Reject requests older than 5 minutes
  if (Date.now() - Number(timestamp) > 5 * 60 * 1000) return false;

  const sourceString = method + uri + rawBody + timestamp;
  const hash = crypto
    .createHmac('sha256', clientSecret)
    .update(sourceString)
    .digest('base64');
  return crypto.timingSafeEqual(Buffer.from(hash), Buffer.from(signature));
}
\`\`\`

**Important:** You must capture the raw request body (before JSON parsing) for signature verification. Use `crypto.timingSafeEqual` to guard against timing attacks.

### Response Contract
- **Return 2xx within 5 seconds** — process events asynchronously
- If you don't respond in 5 seconds, HubSpot treats it as a failure
- HubSpot retries failed deliveries **10 times over 24 hours**

### Batch Handling
Events arrive in batches (up to 100 per POST):
\`\`\`json
[
  { "eventId": 123, "eventType": "contact.creation", "objectId": 456, "portalId": 789, "occurredAt": 1704067200000 },
  { "eventId": 124, "eventType": "contact.propertyChange", "objectId": 456, "propertyName": "email", "propertyValue": "new@example.com", "portalId": 789, "occurredAt": 1704067201000 }
]
\`\`\`

### Idempotency
- Duplicate events are possible — use `eventId` for deduplication
- Event ordering is NOT guaranteed — use `occurredAt` timestamp for ordering
- Use `portalId` to route events to the correct customer context

### GDPR: contact.privacyDeletion (MANDATORY)
When you receive a `contact.privacyDeletion` event:
1. Look up the contact by `objectId`
2. Delete ALL data associated with that contact from your systems
3. Return 2xx to confirm
This is a **marketplace listing requirement**.

## 5. Platform Constraints

- **App object properties are append-only** — once uploaded, properties cannot be removed.
- **App object names are permanent** — they cannot be renamed after first upload.
- **`hs project upload` updates all installs immediately** — no versioning, staged rollout, or version pinning.
- **Uninstalling the app deletes app objects and their data** from the customer's portal.
- **No uninstall webhook** — you cannot be notified when a customer uninstalls.
- **No built-in scheduler** — use an external scheduler (AWS EventBridge, cron) for periodic tasks.
- **Search is eventually consistent** — newly created records may not appear in search immediately.

| Metric | Limit |
|---|---|

| Search API | 5 requests per second per account |
| Batch size | 100 records per request |
| Search results | 10,000 max per query |
| API error rate | Must stay below 5% of daily traffic |
